Locator priority, assertion forms, commands and the rules that prevent flaky tests.

Playwright 1.63.0 · Angular 22 · TypeScript · September 2026

The two rules

Rules

Locate elements by what the user perceives, never by DOM structure.
Express every wait as a retrying assertion, never as a sleep.

Locator priority, stop at the first that fits

LocatorWhen
getByRole('button', { name: 'Save' })Role plus accessible name. Your default choice.
getByLabel('Email')Form fields, via the associated label.
getByPlaceholder('Search')Inputs with no label. Fix the label instead where you can.
getByText('No results')Non-interactive text content.
getByTestId('user-row')Deliberate escape hatch. Add the attribute yourself.
locator('css=...')Last resort. Record why in a comment.

Narrowing

FormEffect
locator.filter({ hasText: 'Ada' })Narrow to elements containing text.
locator.filter({ has: other })Narrow to elements containing another locator.
parent.getByRole('button')Scope inside a row, dialog or list item.
locator.first() / .nth(2)Only when position is the actual subject.

Assertions

FormRetry behaviour
await expect(loc).toBeVisible()Retries. Use this form.
await expect(loc).toHaveText('x')Retries until the text matches.
await expect(loc).toHaveCount(3)Retries until the count matches.
await expect(page).toHaveURL(/re/)Retries until navigation completes.
expect(await loc.isVisible())Does NOT retry. A race. Avoid.

Rules

RuleReason
Never call waitForTimeoutA fixed sleep is usually too short or too long, and often both.
Put await before expectawait expect(loc) retries; expect(await loc) does not.
Never target .mat-mdc-* classesAngular Material renames them between versions.
Fix strict mode by scoping.first() picks an arbitrary element and will eventually pick the wrong one.
Test few journeys, deeplyPush component behaviour down to Angular's own tests.
Do not assert on stylingIt changes for reasons unrelated to correctness.

Diagnosing a failure

  1. Open the trace. npx playwright show-report, then the trace on the failed test. Read the DOM snapshot at the failing step.
  2. Timeout waiting for an element? The locator is wrong, or the element never rendered. The snapshot distinguishes the two.
  3. Strict mode violation? Scope the locator inside its container.
  4. Passes locally, fails in CI? Suspect test data or leaked state between tests before suspecting timing.
  5. Fails only when run with others? Tests share state. Each test must create the data it needs.
