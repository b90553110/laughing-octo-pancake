Commands

CommandWhat it does
./mvnw spring-boot:runRun the app in place, no jar built. Your day-to-day loop.
./mvnw testCompile and run tests only.
./mvnw packageCompile, test, and build the runnable jar into target/.
./mvnw clean packageSame, after deleting target/. Use when results look stale.
./mvnw package -DskipTestsBuild without running tests. For speed; never for CI.
./mvnw dependency:treeShow every transitive dependency. First stop for version conflicts.
./mvnw -o ...Offline: fail rather than reach the network.
java -jar target/app-0.0.1-SNAPSHOT.jarRun the packaged jar the way production will.

pom.xml anatomy

ElementPurpose
<parent>Inherit spring-boot-starter-parent: tested versions for hundreds of libraries.
<groupId>Your organisation, reverse-domain style: com.example.
<artifactId>This project's name: demo.
<version>Yours. -SNAPSHOT means 'in development, not released'.
<properties>Build settings. java.version lives here.
<dependencies>What you need. Omit <version> when the parent manages it.
<scope>test</scope>On the test classpath only; not shipped in the jar.
<build><plugins>spring-boot-maven-plugin builds the single runnable jar.

Annotations you will meet first

AnnotationMeaning
@SpringBootApplicationOn the main class. Config + auto-configuration + component scan.
@RestControllerClass handles HTTP and returns response bodies, not view names.
@GetMapping("/path")Route a GET to this method. Also Post/Put/Delete/Patch variants.
@RequestParamBind a query-string value: /hello?name=Ada.
@PathVariableBind a URL segment: /users/{id}.
@RequestBodyDeserialise the JSON request body into an object.
@Service, @ComponentRegister a class as a managed bean, found by component scan.
@Configuration + @BeanDefine beans explicitly when annotation scanning will not do.

Testing

Annotation / typeUse
@SpringBootTestStart the whole application context. Thorough, slower.
@WebMvcTest(X.class)Web layer only, one controller. Fast; Spring mocks the collaborators.
@AutoConfigureMockMvcAdd MockMvc to a @SpringBootTest.
MockMvcDrive the full request path without opening a socket.
@MockitoBeanReplace a bean with a mock for this test context.

Project layout

PathContains
pom.xmlThe build. Read this first in any unfamiliar project.
mvnw / mvnw.cmdMaven wrapper. Always prefer over a system mvn.
src/main/javaApplication code. Main class at the top package.
src/main/resourcesapplication.properties, static files, templates.
src/test/javaTests, mirroring the main package structure.

Versions that matter

  • Spring Boot 4.1.1 — current stable line as of September 2026.
  • Java 17 minimum for Boot 4, tested through Java 26. Prefer an LTS: 17, 21 or 25.
  • Maven 3.9.0+ — the plugin's hard floor is 3.6.3, but the 3.8 line is end-of-life.
  • Spring Framework 7 underpins Boot 4; Jakarta EE 11, Servlet 6.1.

Boot 3 → 4 gotchas

  • Test slices moved to per-technology modules. @WebMvcTest and @AutoConfigureMockMvc are now in org.springframework.boot.webmvc.test.autoconfigure, from the spring-boot-webmvc-test artifact — add it explicitly.
  • javax.* became jakarta.* back in Boot 3. Any snippet with javax.servlet is pre-2022 and will not compile.
  • Blog posts and generated code alike still use the old test imports. Trust the compiler.

Debugging order

  1. 404 on a route you wrote? Check the controller is in a package below the @SpringBootApplication class.
  2. Port already in use? Another run is alive, or set server.port=8081 in application.properties.
  3. Odd version errors? ./mvnw dependency:tree, and look for a library appearing twice.
  4. Import will not resolve? Suspect a version boundary, then check the artifact is actually a dependency.
